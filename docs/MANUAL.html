How the site works

The 20 web pages are generated. You edit a few source files; one command rebuilds every page from them, so the menu, footer and contact details stay identical everywhere.

  • tools/build_site.py — text & data
  • assets/css/*.css — look
  • assets/js/*.js — behaviour
  • assets/img/… — photos
→python tools/
build_site.py
  • 20 × .html pages
  • site.min.css · *.min.js
  • sitemap.xml · robots.txt · llms.txt
!
Never edit a .html page directly. The next build overwrites it and your change disappears. Change the source file instead, then rebuild.

Editing rules

The content is written in Python. Text sits inside quotes; items are separated by commas. Change only what is between the quotes.

highlighted = the part you change
name='Open Water Diver',    # ✓ change the words inside the quotes
name='Open Water Diver'     # ✗ comma deleted       → build fails
name='Open Water Diver,     # ✗ closing quote gone  → build fails
text='Here's our team'      # ✗ plain ' ends the text early
text='Here&rsquo;s our team' # ✓ use &rsquo; for apostrophes

Special characters

You wantWriteYou wantWrite
&&amp;– (range, 6–8 m)&ndash;
’ apostrophe&rsquo;— (dash)&mdash;
· middle dot&middot;≈&asymp;
i
After every change run python tools/build_site.py. "Done." means your edit is valid. An error message names the line number — check the quotes and commas on that line.

Photo requirements

FormatJPG for photos · PNG only for logos with transparency
Width1600 px for large/hero photos · 1280 px for cards · never under 1000 px
File sizeunder 500 KB before optimising
Namejet-ski.jpg ✓   Jet Ski (1).JPG ✗ — lower case, hyphens, no spaces
ContentYour own photos or ones you have rights to · no other company's name, phone number or watermark

A · Replace (easiest)

  1. Copy the new photo into the same folder.
  2. Rename it to exactly the old name, e.g. kayaking.jpg, and replace.
  3. Run optimise + build (below).

B · Use a new photo

  1. Add my-photo.jpg to assets/img/brochure/.
  2. Change the code: B('cover-divers') → B('my-photo'), and its description text.
  3. Run optimise + build (below).

Always run after any photo change

python tools/optimize_images.py
python tools/build_site.py
i
The optimiser makes small WebP copies (480–1600 px) so phones download less — part of the 90+ Lighthouse score. Browsers may show the old photo for up to a day; press Ctrl + F5 to see the new one.

The publish command

git add -A && git commit -m "Describe your change"; git pull --no-rebase --no-edit -X theirs origin main && python tools/build_site.py && git add -A && (git diff --cached --quiet || git commit -m "Rebuild pages") && git push -u origin main
PartWhat it does
git add -AStages every change (files in .gitignore are skipped)
git commit -m "…"Saves a snapshot with your message — replace the words in quotes
git pull … -X theirsBrings in GitHub's changes (often the daily review bot). Clashes in generated pages resolve automatically
python tools/build_site.pyRebuilds every page with your change and the latest reviews
git diff --cached --quiet || …Commits the rebuild only if something changed
git push -u origin mainUploads to GitHub → Vercel deploys in 1–2 minutes

Before you push

  • Build ended with Done.
  • Previewed at 127.0.0.1:8123
  • Checked phone width, light and dark
  • Ran optimize_images.py after photo changes
  • No API keys or personal files (git status)

After you push

  1. Git Bash ends with … main -> main.
  2. Vercel → Deployments → newest = Ready.
  3. Open www.diveaddaindia.com → Ctrl + F5.

Reviews setup (one time)

  1. Google: console.cloud.google.com → APIs & Services → Library → enable Places API (New) only. Then Credentials → Create API key, restricted to Places API (New). Billing must be on; a daily fetch stays in the free tier.
  2. Tripadvisor: sign up for the Tripadvisor Content API and copy your key.
  3. GitHub: repo → Settings → Secrets and variables → Actions → New repository secret: GOOGLE_PLACES_API_KEY, TRIPADVISOR_API_KEY, optional GOOGLE_PLACE_ID.
  4. Run: Actions → Refresh reviews → Run workflow. Then git pull origin main on your computer.
    ✓ A commit "Refresh Google and Tripadvisor reviews" appears; cards link to each original review.
!
Keys go only into GitHub secrets — never into code or chat.

Troubleshooting

Build prints SyntaxError … line 312
Open that line in tools/build_site.py. A quote or comma is missing, or a plain ' is inside the text — use &rsquo;.
My change isn't on the live site
Did you build and push? Check Vercel → Deployments shows Ready, then press Ctrl + F5 (Mac ⌘ + Shift + R).
nothing to commit, working tree clean
Everything is already saved. Run git push -u origin main.
Your local changes … would be overwritten by merge
You pulled before committing. Use the full publish command — it commits first.
rejected (non-fast-forward)
GitHub has newer commits. Run the full publish command again; it pulls first.
exceeds GitHub's file size limit of 100 MB
A video or zip was included. Keep raw media in static post/ (ignored). The commit has to be redone without the file — ask for help.
CONFLICT … in index.html
Run python tools/build_site.py, then git add -A, git commit -m "Merge and rebuild", git push.
A screen full of ~ lines opened
Git opened its editor (Vim). Type :wq and press Enter.
LF will be replaced by CRLF
A harmless Windows line-ending notice. Ignore it.
npx not found / No module named PIL
Install Node.js LTS, or run pip install pillow, then reopen Git Bash.

Do & never

Do

  • Edit tools/build_site.py, the CSS/JS sources and images
  • Rebuild after every change
  • Record photo sources in CREDITS.txt
  • Check pagespeed.web.dev after big changes — aim for 90+

Never

  • Edit generated files: *.html, *.min.css/js, tailwind.css, manifest.json, sitemap.xml, robots.txt, llms.txt, reviews.json
  • Commit large media, API keys or personal documents
  • Invent reviews, ratings, prices or certifications
